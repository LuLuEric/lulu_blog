# 牌组改版方案与验证

2026-09-13：用户已确认按牌组审查建议实施。目标是让每张牌的总成本、时机和适用场景清楚可见，并改善缺少行动价值的牌。

## 当前问题

- 每轮只有两次行动，提前部署且轮末失效的防护、单纯增加手牌数量的摸牌，机会成本过高。
- 忠诚表态未说清立即判定；交易的总费用未统一；专项摊派在规则文档中方向相反。
- 预览只显示自己的三个数值，无法说明攻击、夺权、换牌、防护和后续代价。
- 旧版 300 局现有电脑策略模拟：挡箭牌使用 720 次，其中 148 次已无本轮后续对手；没有清洗。该结果用于定位问题，不证明真人玩法平衡。

## 已确认的实施方向

| 卡牌 | 第一版规则 |
| --- | --- |
| 挡箭牌 | 被举报、夺权、栽赃或一致通过指定时，可支付 2 影响力并弃置本牌拦截。不占自己的行动，每次攻击只有一次响应，不引入反制链。 |
| 秘密交易 | 合计 3 影响力，其中 2 给对手；自己立即 +5 宠幸；选择自己另一张手牌，交换对手随机一张。 |
| 机密档案 | 1 影响力，不占行动；弃一张其他手牌，摸两张。每次自己的行动阶段限用一次，不能循环使用。 |
| 极端表忠 | 1 影响力和 20 忠诚，立即 +18 宠幸；须足额支付，不再新增延迟债务。 |

其余牌澄清时机和实际数值。第一版模拟后保留专项摊派的 3 费；纪律整顿费用 4→3，栽赃嫁祸的忠诚伤害 8→15，突出早期经济和忠诚干扰，不普遍增加宠幸收益。

## 模块与状态

- `data.js` 统一总费用、额外忠诚费用、行动次数与牌面文字。交易的总费用包含给对手的部分。
- `engine.js` 保留原行动者，增加一次攻击的待响应状态；响应者只能拦截或接受，响应结束后原行动者继续。响应过程可保存和重放。
- `ai.js` 只观察当前决策者自己的手牌与公开信息；分别评估普通行动、指定的换出牌和防护响应。返还资源按先支付后的实际净变化计价。
- `preview.js` 汇总双方数值、手牌数量、机构、保护、调查和行动变化。随机换入/摸入牌只显示数量；攻击始终按可能被拦截提示，不通过预览泄漏对手的挡箭牌。
- `app.js` 提供换出牌选择、受袭选择、费用与完整效果预览；当前预计收入先考虑轮末忠诚下降，并明确未计未来事件。
- 存档升级到新版本，新存储项保留旧项作为原始副本；旧版未清债务和已部署护盾继续履约，不因升级消失。

## 验证目标

1. 先补失败用例：响应双方权限、接受/拦截四类攻击、无牌/无预算、末轮、调查宽限、保存恢复和重放。
2. 覆盖交易选牌下标与费用边界、换牌循环限制、极端表忠足额支付、上限截断、忠诚即时奖励。
3. 预览与实际数值一致，预览不改变随机状态，不显示未知手牌或未来摸牌；旧存档的债务与护盾保持。
4. 运行完整自动测试与固定种子电脑对局，记录可用时的使用率、反应次数、清洗与终局；对称策略单独检查座次。
5. 浏览器实际检查选牌、受袭选择、取消/关闭、刷新续玩、末轮以及窄屏布局。自动模拟不能替代人工试玩平衡结论。

## 当前状态

已实现并完成本地验收：48 项测试通过，最终规则的 300 局差异策略和 1,000 局对称策略通过每步校验；浏览器完成各关键选择、刷新恢复、窄屏交易与 12 轮闭幕。详细数据及发布状态见 `VERIFICATION.md`。

仍未关闭的平衡问题：1,000 局对称策略中只发生一次清洗，存活者终局平均宠幸 90.71。防护已能实际使用，交易和换牌选择也可兑现，但这些数据不能证明竞技平衡或首次玩家理解度。
