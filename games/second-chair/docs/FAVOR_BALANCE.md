# v0.2.1 宠幸收支调整

## 结论与范围

用户试玩确认多人频繁满宠幸，并已同意先测试三项调整。目标是降低常态满值和终局拥挤，同时保留调查后的完整自救机会。本轮不改变极端表忠、挡箭牌、清洗门槛和调查期限。

| 项目 | v0.2.0 基线 | v0.2.1 已实现 |
| --- | --- | --- |
| 集体颂词 | 自己 +12，其他存活者各 +3 | 自己 +10，其他存活者各 +1 |
| 强力宣传 | +8 宠幸，支付 3 后返还 2 影响力 | +6 宠幸，支付 3 后返还 1 影响力 |
| 轮末基础损耗 | 3 宠幸，另计猜忌 | 5 宠幸，另计猜忌 |

## 阅读指南

- 本文说明为何收紧宠幸、改动范围，以及相同种子下的实际结果。
- 先读“结论与范围”和“对照结果”；维护时再读“实现与验证顺序”和“复现与证据”。
- 三项数值与自救边界一起评估；电脑样本不代表人工平衡已完成。

## 问题与选择原因

v0.2.0 的 300 局只读分析中，82.83% 的官员曾满宠幸，终局平均 90.9，无人进入调查。每人每轮实际获得 10.53、损失 7.12，收益持续大于损耗；集体颂词占实际宠幸增量 34.36%。

集体颂词修改后仍让使用者相对每位同僚领先 9 点，但四人存活时全桌增量从 21 降至 13。宣传仍是低费得分牌，净费用从 1 增至 2。基础损耗覆盖所有官员，使经营与得分之间需要持续分配行动。

## 实现与验证顺序

1. 固定当前发布提交 `29777d783119a2c008d18f2c95a788d181cfbabf` 的 32 个文件及 SHA-256，作为独立对照源。
2. 将两个卡牌收益和基础损耗集中到数据定义，由结算、电脑策略和界面读取；同步规则、费用文案与版本号。
3. 回归支付边界、宠幸封顶、全体效果、轮末预览与实际结算一致性，以及调查自救和终局审查。
4. 同一脚本、相同种子分别运行新旧版本，记录满值官员比例、首次满值轮次、轮末分布、最高宠幸并列、调查、自救、清洗及座次胜率。
5. 浏览器实际检查新卡面、费用与收益、轮末说明、刷新恢复；通过后按现有 GitHub 发布流程记录版本。

固定种子前缀为 `FAVOR-AUDIT-20260913-`。300 局使用现有不同电脑偏好；另用 1,000 局相同偏好检查座次差异。自动测试和模拟只能证明规则行为及该策略下的分布，人工平衡仍需试玩。

## 对照结果

53 项测试通过、0 失败。新增五项在旧规则下均失败、修改后通过，覆盖先付后返、满值截断、全桌及淘汰者效果、猜忌边界、完整自救机会和终局 19／20 分界。300 局旧版统计复现前次只读分析的关键数值。

| 指标 | 300 局旧版 | 300 局新版 | 1,000 局旧版 | 1,000 局新版 |
| --- | ---: | ---: | ---: | ---: |
| 曾满宠幸的官员比例 | 82.83% | 8.42% | 81.40% | 5.85% |
| 四人都曾满值的对局 | 158 | 0 | 510 | 0 |
| 首次满值平均轮次（仅满值者） | 8.24 | 9.74 | 8.22 | 9.92 |
| 存活者终局平均宠幸 | 90.90 | 64.57 | 90.53 | 60.85 |
| 存活者终局至少 90 的比例 | 68.25% | 6.73% | 65.67% | 4.82% |
| 最高宠幸并列的对局 | 88 | 15 | 341 | 47 |
| 调查次数 | 0 | 28 | 2 | 135 |
| 解除调查次数 | 0 | 17 | 2 | 77 |
| 通过本人行动自救次数 | 0 | 17 | 2 | 74 |
| 被清洗官员数 | 0 | 11 | 0 | 58 |

1,000 局新版中，另有 3 次调查由他人帮助或公共事件解除。四批对局均正常结束并逐步通过状态校验，全部存在获胜者。统计是同种子下两套规则及其对应电脑估值的对照，不是三项改动分别产生多少效果的独立因果试验。

相同策略座次胜率：旧版 26.42%／23.45%／23.88%／26.25%，新版 23.00%／26.55%／25.95%／24.50%。新版前四轮轮末均值约 53.6～53.8，第 8 轮为 56.42，第 12 轮为 60.85，常态满值现象明显减少。

差异策略新版中，机构经营者胜率 34.67%，其余座次 19.67%～23.67%；角色偏好与座次绑定，不能作为座次公平结论。经营优势、人工自救难度和清洗压力仍需试玩，不在本次三项范围内额外调参。
